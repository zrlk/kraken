# Litmus corpus

Regression corpus for Kraken's weak-memory model (`Kraken/Promising/`,
`krakenlitmus_aarch64`, `krakenlitmus_x64`): herd7 litmus tests together
with herd7's own output on each, which is the oracle `litmus_tests.py`
compares against.

`aarch64-views/` is not from herdtools7: it is generated with diycross7 by
its [gen.sh](aarch64-views/gen.sh) (plus the hand-written tests in
`aarch64-views/hand/`) and exercises the thread-local view rules (which
earlier accesses `DMB ST`, `DSB ST`, `DMB LD`, `DSB LD` and release stores
order), and per-access data dependencies of pair stores (`hand/LB+datapair*`,
`hand/LB+pair-tworeads*`, `hand/MP+dmb.st+addr-ldp`: each half of an `STP`
depends only on its own data register; `hand/MP+dmb.st+stp-wb`: `STP`'s
written-back base depends on no data register, unlike `STR`'s,
`hand/MP+dmb.st+wb`). Its oracle files are produced by
`gen.sh`, not `refresh.sh`.

`aarch64-noret/` is generated the same way by its
[gen.sh](aarch64-noret/gen.sh): diycross7 families over the no-result
atomics diy emits (`STADD`, `STCLR`, `STEOR`, `STSET`), the zero-destination
`LD<op>`/`SWP`/`CAS` forms written by [gen_zr.py](aarch64-noret/gen_zr.py)
(diy cannot emit them), and `aarch64-noret/hand/` (failing `CAS` with
comparand `WZR`). It exercises herd's `NoRet` reads: not ordered by
`DMB LD`/`DSB LD`, never acquires, ordered by `DMB SY`/`DSB SY` and release
stores.

`aarch64-pairs/` is generated by its [gen.sh](aarch64-pairs/gen.sh):
diycross7 families over diy's `LDP`/`STP` pair annotation (`Pa`; diy has no
edges for exclusive pairs or `CASP`) and the hand-written tests in
`aarch64-pairs/hand/`: `LDXP`/`LDAXP`/`STXP`/`STLXP` on a 16-byte location
and on arrays, both orders of `CASP`'s halves for every kind (`-rd01/10`,
`-wr01/10`), `CASP` failure, `CAS`/`CASP` fail-with-write-back probes, the
missing data dependency of store exclusives (herd's `read_reg_ord`) with
controls, and mixed sizes. Tests typing a location wider than its accesses
are run with herd's `-variant mixed`. `aarch64-pairs/lse2/` holds FEAT_LSE2
tests with hand-argued `.litmus.lse2` oracles (`litmus_tests.py --lse2`;
herd has no FEAT_LSE2), and `aarch64-pairs/open/` tests where Kraken is
stricter than herd, outside the regression run (see its README).

The `*.litmus.herd` files are herd7's output on each test (its `Time` and
`Hash` lines removed), produced by [refresh.sh](refresh.sh), which also
refreshes the corpus from a herdtools7 checkout.

`x86_64-vector/` is not from herdtools7: it is written for Kraken, with
hand-argued expected outputs (`*.litmus.hand`), since herd7 has no vector
instructions; see its [README](x86_64-vector/README.md).

`x86_64-nt/` is generated by its [gen.sh](x86_64-nt/gen.sh): the sweep's
x86_64 tests that use `movnti` (diy's `NT` annotation), plus
`x86_64-nt/hand/`. Kraken's non-temporal stores follow the Intel SDM and are
weaker than herd's (herd treats `movnti` as a TSO store). Where they differ,
a hand-argued `<test>.litmus.sdm` oracle, written by the independent SDM
model `x86_64-nt/sdm_model.py`, replaces `.herd`. `litmus_tests.py` checks
that it contains every herd state and marks the row `(SDM, weaker than
herd)`; see its [README](x86_64-nt/README.md).

## Running

    lake build krakenlitmus_aarch64 krakenlitmus_x64
    python3 Kraken/Litmus/litmus_tests.py Kraken/Litmus/corpus/aarch64
    python3 Kraken/Litmus/litmus_tests.py Kraken/Litmus/corpus/aarch64-views
    python3 Kraken/Litmus/litmus_tests.py Kraken/Litmus/corpus/aarch64-noret
    python3 Kraken/Litmus/litmus_tests.py Kraken/Litmus/corpus/aarch64-pairs
    python3 Kraken/Litmus/litmus_tests.py --isa x64 Kraken/Litmus/corpus/x86_64
    python3 Kraken/Litmus/litmus_tests.py --isa x64 Kraken/Litmus/corpus/x86_64-nt Kraken/Litmus/corpus/x86_64-nt/hand
    python3 Kraken/Litmus/litmus_tests.py Kraken/Litmus/corpus/lowering/aarch64
    python3 Kraken/Litmus/litmus_tests.py --lse2 Kraken/Litmus/corpus/lowering/aarch64/lse2
    python3 Kraken/Litmus/litmus_tests.py --isa x64 Kraken/Litmus/corpus/lowering/x64

### herd's `Loop` pseudo-state

For a test with a retry loop herd cuts its unrolling short and prints a
`Loop Ok` (or `Loop No`) line among the states. It is not a final state, and
Kraken (which runs loops under its `-fuel` budget) never prints one, so
`litmus_tests.py` drops it from the oracle before comparing: the test is
compared on its real states and its `Observation` word only. Such rows are
marked `(herd Loop)` and the summary line counts them ("N compared without
herd's Loop pseudo-state"). Only the oracle's `Loop` lines are dropped, so a
real-state difference is still a mismatch; `selftest/check_loop.py`
(`Kraken/Litmus/selftest/`) checks that on doctored oracles. In this corpus
A184 and L029 carry one (`aarch64-instructions`); A184 agrees on its real
states, L029 does not (herd prunes its unrolling and has no real state at
all; see `../KNOWN_GAPS.md`).
