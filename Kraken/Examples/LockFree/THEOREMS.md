# LockFree examples: theorem index

One row per `.kl` program of [`AArch64/`](AArch64/README.md) and
[`X64/`](X64/README.md): every Lean theorem about it, by kind.
Names are fully qualified; files are relative to `Kraken/`. Every name
below is checked with `#check` (see "Regenerating" below).
Each `.kl` header carries the same information in its `Proved…`,
`Counterexample…` and `Open…` comment lines (and `# Proved reachable:`).

**Stages.** Docstrings, `.kl` headers and the gap lists (`Litmus/KNOWN_GAPS.md`,
`Promising/EnvWP.md`) group the LockFree work into four stages:

- **Stage 1**: bounded checks. The explorer runs each `.kl` program with a
  fixed number of threads and operations, and the fixed instances are Lean
  theorems by evaluation (`TheoremsAArch64.lean`, `TheoremsX64.lean`).
- **Stage 2**: safety for any number of threads. A promise-free,
  thread-modular logic (environments, rely/guarantee) over `Reachable` proves
  each program's property (mutual exclusion, counters, data-structure
  invariants): the safety and no-fault columns below. LL/SC loops are deferred
  in this logic.
- **Stage 3**: liveness of the locks under fairness. Fair traces, weak and
  memory fairness, and the store-exclusive progress hypothesis; lock
  acquisition terminates (ticket-lock liveness, spinlock deadlock-freedom), or
  a counterexample shows it need not: the liveness column.
- **Stage 4**: lock-free data structures and repeated acquisition:
  termination of the Treiber-stack workers on the semantic machine
  (`Promising/LiveTerm*.lean`), and liveness of the repeated-acquire ticket
  lock (`ticketlock_loop{2,3}.kl`, `Promising/LiveTicketLoop*.lean`).

Columns:

- **Whole-image safety**: the `.kl`'s property at every final configuration
  reachable from the program's start states, with every thread running the
  `.kl`'s `code` block (the whole image, from its entry label to its exit
  label) over every layout, at `decls = {}` (the x64 vector programs
  `publish_movdqa` and `treiber_aba_tagged` are stated with declarations). A `_concrete…` theorem is the
  instance at the runner's layout, checked against the runner by a
  `codeMatches`/`runnerMatches` `#guard_msgs #eval`. "also" lists the
  earlier forms (per-thread image, symbol operands as registers, pre-EnvG
  cell route), all kept.
- **Runner-exact safety**: the same property from the runner's exact
  configuration (its declarations `decls = ds` and its initial memory;
  `runnerIsD`/`runnerMatchesD` checks). The `*_runner` theorem is stated for
  every strict sized `ds`; the `_concrete…` one is the runner's.
- **No-fault**: rule-level `NoFaultRule` (no thread step faults from the
  rule's invariant), at `decls = {}` and at the runner's declarations.
  Program-level fault freedom (`Config.FaultFree`) has its own tables below.
- **Safe ∧ `FaultFree` (runner)**: one theorem that concludes both the
  runner-exact safety property and program-level `Config.FaultFree` from the
  runner's exact configuration (`Promising/SLR/EnvG/RunnerSafeFF{A64,X64}.lean`):
  the generic `*_runner_safe_faultFree` and its concrete instance.
- **Reachability**: `∃ c, Reachable A fuel c0 c ∧ c.final ∧ …` for the
  violating final state of a `Sometimes` file, from the runner's initial
  configuration (`Litmus/KNOWN_GAPS.md`, "Reachability theorems for the
  `Sometimes` LockFree examples"; promise witnesses are certified by
  `Promising/ReachCertCore.lean`).
- **Liveness**: the Stage 3 statements and counterexamples
  (`Promising/Live*.lean`).
- **Open gaps**: what is not proved, with the `KNOWN_GAPS` entry.

**`_sem` twins.** The safety and fault-freedom theorems above
are about the executable machine (`Reachable`, `Config.FaultFree`). Each one
that mentions them has a twin `…_sem…`, listed under "also" in the
whole-image column. The twin has the same statement with `Reachable A fuel c₀ c`
replaced by `ReachableSem A fuel c₀ c` (the semantic machine: promises
certified semantically, with the same fuel binder now the certification
fuel), and `Config.FaultFree` replaced by `Config.FaultFreeSem`. The name
puts `_sem` before the first `_concrete`; otherwise `_sem` is appended,
before any trailing primes. The twins are generated by `#sem_twin`
(`Promising/SLR/ChainK/SemTwin.lean`) from the K-world clones of the
originals. [`SEM_TWINS.md`](SEM_TWINS.md) lists every twin with its
statement, and `python3 Kraken/Examples/LockFree/tools/sem_twins.py`
re-checks every twin statement independently. Two x64 theorems have no twin:
`X64.EnvG.VecPublish.x64_publish_movdqa_verbatim(_faultFree)`. They are
stated for a general start configuration, not a `Config.init`, so the
transport's boundedness side condition is not available
(`Litmus/KNOWN_GAPS.md`, "The executable checker vs the semantic machine").

**`_semInf` twins: the fuel-free machine (P2).** Each `_sem` twin has a
fuel-free twin `…_semInf…` on `ReachableSemInf`/`Config.FaultFreeSemInf`
(`Promising/LiveSemInf.lean`: the semantic machine with unbounded
certification `CertOk`, the target for lowering). The `∀ fuel` binder is
dropped; `ReachableSemInf A c c' ↔ ∃ fuel, ReachableSem A fuel c c'`
(`reachableSemInf_iff`). The twins are generated by `#inf_twin`
(`Promising/SLR/ChainK/InfTwin.lean`). The 16 CertBounded headlines
(`spin_cas_live*_semU*`, the `treiber2*` termination family) are restated as
`…_semInf…` by `#semU_inf_twin` (`Promising/LiveCertBoundedInf.lean`).
[`INF_TWINS.md`](INF_TWINS.md) lists all of them, and
`python3 Kraken/Examples/LockFree/tools/inf_twins.py` re-checks them
(`Litmus/KNOWN_GAPS.md`, "The fuel-free semantic machine").

## Lowering

Whole-program theorems for lowered source programs (WeakCore's lock-free
structures compiled to AArch64/x64 fragments), and the kit, bridge and
fragment-spec rules they are built from. The guide is
[`Promising/Lower/README.md`](../../Promising/Lower/README.md). Every name in
this section is checked by
[`Promising/Lower/Headlines.lean`](../../Promising/Lower/Headlines.lean)
(AArch64) or
[`HeadlinesX64.lean`](../../Promising/Lower/HeadlinesX64.lean) (x64): a
`#check` per name and, for the headlines, `#print axioms` under
`#guard_msgs` (all `propext`, `Classical.choice`, `Quot.sound`), so the
default `lake build` fails if one disappears or gains an axiom. Names are
relative to `Kraken.Promising`; files to `Kraken/Promising/Lower/`.

Machines: `…_promising` and `…_concrete` conclude on the executable machine
`Reachable` (`Arch.armv8` for AArch64, `Arch.tso` for x64). On `isaLSE2`
(FEAT_LSE2, WeakCore's AArch64 target) `…_lse2` is the executable machine,
`…_lse2_sem` `ReachableSem`, `…_lse2_semInf` the fuel-free
`Live.Inf.ReachableSemInf`. Each conclusion holds at every reachable final
configuration. **Start only** means every hypothesis is about the start
states and the initial memory; a `_concrete` form discharges them at a fixed
layout. **Conditional** theorems carry an obligation that is not about the
start states.
